## Corrections

**Q1.** `a == b` is `true`. Both literals resolve to the same entry in the string pool, so `==`
compares equal references by accident. `new String("test")` forces a heap object → `a == c` is
`false`. `equals` compares characters → `true`. Trap: `"te" + "st"` is folded at compile time and
still pooled, but `variable + "st"` is a runtime object and `==` fails.

**Q2.** Reasoning correct. Nuance: `StringBuilder` is the default; `StringBuffer` is the
synchronized variant and is slower — only for genuinely shared buffers. Also name the cost: n
concats copy 1 + 2 + ... + n characters → O(n²).

**Q3.** `ArrayList` = resizable array: `get(i)` is O(1), insert at front is O(n) because everything
shifts. `LinkedList` = doubly linked nodes: `get(i)` is O(n) because it walks the chain, insert at
front is O(1). Trap: `list.add(500_000, x)` on a `LinkedList` is still O(n) — it walks to the index
first. `LinkedList` is rarely the right answer; `ArrayDeque` is the usual queue.

**Q4.** The bucket is chosen by `hashCode`. With only `equals` overridden, two equal objects get
identity hashes and land in different buckets, so `get` misses and a `Set` stores duplicates. The
contract: equal objects must return equal hash codes. Override both, and never use mutable fields.

**Q5.** On `Stream<List<String>>`, `map` keeps the nesting (`Stream<List<String>>`); `flatMap`
flattens one level (`Stream<String>`). A stream is a one-shot pipeline: a terminal operation
consumes the source, and reusing it throws `IllegalStateException: stream has already been operated
upon or closed`. Rebuild it from the source or `collect` first.

**Q6.** `throw` takes a `Throwable` instance; `throws` declares what a method may propagate. `finally`
is skipped by `System.exit()`, a JVM crash or forced kill, and a thread that never leaves the
`try` (infinite loop). It does run on `return`, `break`, and exceptions. Trap: returning from
`finally` swallows exceptions.

## Follow-up (asked, not graded)

**"If try and finally both return, which wins?"** Answered with a runnable demo
(`FinallyReturn.java`, temp, not committed):

| Case | Result |
|---|---|
| `try { return 1; } finally { return 2; }` | `2` — finally overrides |
| `int c = 0; try { return c++; } finally { c += 100; }` | `0` — value evaluated first |
| `try { throw ...; } finally { return 42; }` | `42` — exception swallowed |
| `try { return sb; } finally { sb.append("b"); }` | `ab` — reference, not copy |

Rule: `finally` runs after the return value is computed and before the method exits; a `return`
there replaces the result and discards any in-flight exception. `javac -Xlint:finally` warns
"finally block does not complete normally".
