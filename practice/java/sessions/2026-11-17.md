# Session 2 — 2026-11-17 — Collections, from zero

Starting point: "I know a bit of theory but can't handle collections in code."

## Taught

1. **Mental model** — `List` = numbered shelf (index), `Map` = dictionary (key), `Set` = guest
   list (no duplicates). Same method name, different question: `list.get(1)` vs `map.get("x")`.
2. **Counting idiom** — if/else → `getOrDefault` → `merge`, all three shown working.
3. **Set implementations** — `HashSet` (hash order) vs `LinkedHashSet` (insertion order) vs
   `TreeSet` (sorted); cost and when to use each.
4. **`TreeMap`** — sorted on insert, `new TreeMap<>(counts)`, `entrySet()` printing, reverse
   `Comparator`, keys must be `Comparable`, no `null` keys.
5. **`println(map)` works** — `AbstractMap.toString()` is already the loop; `int[]` and classes
   without `toString` print identity hashes.
6. **`split` takes a regex** — `split(" ")` vs `split("\\s+")`, trailing empties, `split(".")`
   returning an empty array.

## Misconceptions found

- "A duplicate key is an error" → a `Map` holds one value per key; `put` replaces and returns the
  old value. Collections signal failure with return values (`add` → `false`), not exceptions.
- `new Set` → `Set` is an interface; declare the interface, instantiate `LinkedHashSet`.
- Generic type arguments are reference types (`Integer`, `Character`), never `int`/`char`.
- `split(" ")` is a literal-looking regex; assume whitespace is `\\s+`.
