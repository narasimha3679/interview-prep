## Taught

1. **A locator is a lazy query, not an element** — Selenium's `findElement` takes a photo; a Playwright
   `Locator` keeps a bookmark and only looks at the DOM when you act on it.
2. **Auto-waiting** — `click` / `fill` / `expect` retry the lookup and the actionability checks until
   the timeout. This is why `waitForTimeout` is a bug and not a fix.

Demo: `projects/playwright/` executed for real. `login.spec.ts` on chromium → **3 passed (4.7s)**,
no sleeps anywhere in the spec.

```ts
await loginPage.login(username, password);          // fill, fill, click — no waits
await expect(inventoryPage.heading).toBeVisible();  // web-first assertion
```

## Framework audit — is `projects/playwright` enterprise?

Asked before starting drills, because it is the artifact to quote in "how would you build this from
scratch". Verdict: **interview-grade reference implementation, not enterprise**. Do not claim
"enterprise"; claim the scope and name the gaps.

Holds up: TS strict + `noEmit`, typed POM fixtures per test, role/placeholder/testId locators, POM
with no business assertions, `fullyParallel` + 3 browser projects, trace/screenshot/video on failure,
CI installs browsers and uploads the report.

Gaps found (interview-relevant):

| Gap | Why it scores | Cost |
|---|---|---|
| No auth `storageState` setup project — every spec drives the login UI | The #1 expected answer; UI login in every test is the classic junior pattern | ~30 min |
| No API setup / seeding layer | "How do you avoid clicking through setup?" has no honest answer today | needs a non-UI-only app or mocks |
| CI: no `tsc --noEmit`, no sharding, no JUnit, single job × 3 browsers | "Have you run this at scale" collapses | ~30 min |
| Env config falls back silently (`?? 'standard_user'`) | Wrong env should fail fast, not test the wrong thing | ~15 min |
| Suite depends on a public external site | "What if saucedemo is down?" has no answer | design note |
| Tags live only in title strings; no tag convention | `--grep` works, but no smoke/regression policy | ~15 min |

Not worth closing for this round: lint/format, visual regression, mobile projects, Docker, Dependabot.

Plan change: framework hardening (auth + CI + fail-fast config) moves ahead of the mock interview.
API layer needs a decision first — saucedemo has no REST API, so either mock with `page.route` or
point the framework at an API-first demo.

## Deliverable — `projects/playwright-enterprise/`

Requested because the first project was AI-generated and cannot be defended line by line. Built from
a clean slate rather than patched, so the two folders can be diffed. Original `projects/playwright/`
left untouched.

Stack: Playwright 1.65.1, TypeScript 5.9 strict, zod 4.6.7, ESLint 9 type-aware, Prettier 3.
App under test: saucedemo (UI) + restful-booker (API). Both demo services, both verified reachable.

Verified by running, not by inspection:

- `npx playwright test` → **13 passed** (1 setup + 7 UI + 5 API), ~3–4s.
- `npm run test:api` → **5 passed**, no browser, no setup dependency.
- `npm run verify` → typecheck + lint + format clean, exit 0.
- Fail-fast proven: `WEB_BASE_URL=not-a-url npx playwright test --list` → `Invalid environment
  configuration: - WEB_BASE_URL: Invalid URL`.
- `npm audit` → one high-severity `zod` advisory found and fixed by upgrading 3.x → 4.6.7; now 0.

Enterprise patterns now present as running code: setup project + `storageState`; role map; typed
fixtures with worker-scoped API token; teardown fixture that deletes created records after failures;
zod-validated env; zod-validated API responses; POM with no assertions; `test.step`; `page.route`
resilience; JUnit + HTML + blob reporters; CI quality gate → shards → merged report; type-aware
lint with `no-floating-promises`.

Two quirks found by running and documented instead of hidden: saucedemo refuses `/inventory.html`
without a session in place (error text, no redirect), and restful-booker returns **405**, not 404,
when deleting an already-deleted booking — cleanup tolerates both.
