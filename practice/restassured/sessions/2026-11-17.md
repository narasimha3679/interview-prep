## Corrections

**Q1.** Structure right, details wrong — `body` inside `given()`, method + endpoint inside `when()`:
that is the part that matters and it was correct. Four defects:

1. `baseurl` → `baseUri` (case-sensitive method; `baseUrl` is only a config *key*).
2. `.header("authorization : barrer token")` — no single-argument `header()` overload exists, so this
   does not compile. It is `.header("Authorization", "Bearer " + token)`: name, value, capitalised,
   "Bearer" spelled correctly.
3. No `.contentType(ContentType.JSON)`. With a POJO/Map RestAssured can infer JSON; with a raw
   `String` body it does not, and the server answers `415 Unsupported Media Type`.
4. `.then()` with nothing after it asserts nothing — a `500` would still pass. Needs
   `.statusCode(201)` at minimum.

Trap: an empty `then()` looks like a finished test to the eye and to the compiler.

**Q2.** Blank. Correct model: `.auth().basic(u,p)` is *challenged* — request 1 goes out with no
`Authorization` header, the server answers `401` + `WWW-Authenticate: Basic`, and only then does
RestAssured retry with the header. Two round trips. `.auth().preemptive().basic(u,p)` puts
`Authorization: Basic base64(user:pass)` on the first request. One round trip, and what most APIs
expect. Base64 is encoding, not encryption — HTTPS is what protects it.

**Q3.** Right instincts, missing the vocabulary the panel listens for. "Helper class that builds the
given" = **`RequestSpecification`** (`new RequestSpecBuilder().setBaseUri(...).setContentType(...)
.addHeader(...).build()`), and the per-test form is `given().spec(reqSpec)`. Env config in an
external file is correct (`ConfigManager.get("api.baseUrl")`); token helper is correct; but the
interview answer names the two classes and says *"the POM of API testing"*. Also: token from a
helper should be **cached** and refreshed on expiry/401, not regenerated per test. Note the
mislabel — the file is config, not a "datalist".

**Q4.** Both make the same HTTP call; the difference is what happens to the value. Inline
`.body("id", equalTo(5))` asserts and throws the value away. `.extract()` pulls it into Java for the
next request (chaining), a DB comparison, or a data provider. Rule: assert only → inline; need the
value → extract. They compose: `.then().body("name", notNullValue()).extract().path("id")`.

**Q5.** Half-grasped, scored 1. The mechanism is the **boundary**. A multipart body is
`--boundary` + headers + bytes + `--boundary`, repeated, and the boundary string is random per
request. The `Content-Type` header must name that same boundary. Set the header by hand and the
server gets `multipart/form-data` with no boundary to split on, so it cannot find the parts —
commonly `400`, sometimes a truncated/empty upload. `.multiPart(...)` sets the header *and* the
boundary together. Never set it yourself.

## Misconceptions found

- Believed `header()` takes one `"name: value"` string (works in cURL, not in RestAssured) → two args.
- Believed the chain ends at `then()` → `then()` is where the assertions start.
- Reached for a bespoke "request builder helper" before naming `RequestSpecification`.
- Read `Content-Type` as a label you *declare* rather than a header the library must *generate* for
  multipart.
