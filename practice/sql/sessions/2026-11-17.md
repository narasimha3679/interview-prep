## Taught

1. **A status code is not persistence.** `201` / `200` proves the API accepted the request. The
   second assertion — read the row back — is what proves the write. A suite that stops at
   `statusCode(201)` can be green while nothing is stored.
2. **JDBC, five lines that matter:** `DriverManager.getConnection` → `prepareStatement(sql with ?)`
   → bind parameters → `executeQuery` → `rs.next()`, all inside try-with-resources so the
   `ResultSet`, `Statement` and `Connection` close in reverse order even when an assertion throws.
3. **`PreparedStatement` over `Statement`:** `?` placeholders mean the value is data, never SQL text
   (injection), and the statement is precompiled by the driver.
4. **Async services are eventually consistent.** The embedded API answers `201` and inserts 300 ms
   later, so an immediate query legitimately finds nothing. Poll to a deadline rather than
   `Thread.sleep(big number)` — sleep is simultaneously too slow when it works and too short when
   the box is loaded.
5. **Cleanup is part of the test.** `DELETE ... WHERE id = ?` and assert the update count. Unscoped
   `DELETE`, `TRUNCATE` and `DROP` are how a test suite empties a shared environment.
