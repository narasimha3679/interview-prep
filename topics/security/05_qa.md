# 05 — Security Q&A

**S1. What is the difference between authentication and authorization?**
> "Authentication proves identity; authorization decides access. Authentication failure is 401;
> authorization failure is 403 (or 404 if the policy hides existence). I test both, including
> object-level, function-level, and tenant-level access."

**S2. What is broken access control?**
> "A user can act outside their intended permissions — read another user's order, call an admin
> endpoint, or cross a tenant boundary. It is the #1 OWASP risk. I test it with an access matrix and
> by swapping IDs/roles/tenants."

**S3. What is IDOR?**
> "Insecure direct object reference: an endpoint accepts an object ID and doesn't verify ownership.
> Test by using another user's ID and expecting 403/404, not 200 with their data."

**S4. How do you test authorization?**
> "Build a matrix of endpoints × principals (anonymous, user A, user B, admin, tenant B). Test every
> cell, including nested resources and GraphQL fields. Automate it as data-driven tests."

**S5. What is mass assignment?**
> "Binding client input directly to an internal object lets a client set fields it shouldn't, like
> `role` or `status`. I send privileged fields and assert they are ignored or rejected. The fix is an
> explicit DTO allowlist."

**S6. How do you test injection?**
> "Send malicious input through every channel — path, query, header, body, nested JSON, filenames —
> and assert validation/parameterization. SQL/NoSQL/OS/LDAP/template injection are the main classes."

**S7. What is SSRF?**
> "Server-side request forgery: the server fetches a URL supplied by the attacker, potentially reaching
> internal services or cloud metadata. Test by blocking localhost/private ranges/metadata IPs and
> using an allowlist."

**S8. How do you test rate limiting?**
> "Burst above the limit and assert 429/error with retry guidance. Check it's per user/tenant, not just
> global, and that expensive endpoints have stricter limits."

**S9. How do you test JWT auth?**
> "Valid token works; missing/malformed/expired/wrong-signature/wrong-audience/wrong-scope/revoked
> tokens fail. Check claims, rotation, and that sensitive data isn't in the payload."

**S10. How do you handle secrets in tests?**
> "Inject from a secret store/CI secret, never commit or log them, mask reports, use short-lived
> credentials/managed identity, and scan for leaks."

**S11. What is the OWASP Top 10?**
> "The most critical web application security risks: broken access control, cryptographic failures,
> injection, insecure design, misconfiguration, vulnerable components, auth failures, integrity
> failures, logging/monitoring failures, and SSRF."

**S12. What is the OWASP API Top 10?**
> "API-specific risks: object-level auth, broken auth, excessive data exposure, rate limiting,
> function-level auth, mass assignment, misconfiguration, injection, inventory management, and unsafe
> third-party consumption."

**S13. What does ZAP catch?**
> "Generic DAST findings: headers, cookies, TLS, information disclosure, some injection/XSS. It does
> not understand business logic or complex authorization. I combine it with manual/pen-test review."

**S14. How do you test file uploads?**
> "Content type vs actual content, size, filename traversal, double extension, malware scan, image
> bombs, download authorization, and signed URL expiry."

**S15. How do you test webhooks?**
> "Signature verification, replay protection, idempotency, destination allowlist, timeout/retry, and
> duplicate delivery."

**S16. How do you test multi-tenant isolation?**
> "Tenant A token + tenant B object/list/filter/search/cache/event. Every path must deny or scope.
> Background jobs and admin access must be explicit and audited."

**S17. What is excessive data exposure?**
> "The API returns more data than the client needs — internal IDs, emails, tokens, stack traces. I
> inspect the full response and assert the contract, including GraphQL field-level access."

**S18. How do you test error handling for security?**
> "No stack traces, SQL, internal paths, or user enumeration. Consistent error codes. Login/reset
> responses shouldn't reveal whether an account exists."

**S19. How do you integrate security into CI?**
> "Secrets scan, dependency scan, static analysis, unit/API auth tests on PR; ZAP baseline on
> staging/nightly; container/IaC scan; critical/high findings block release with owned exceptions."

**S20. What can't automation catch?**
> "Business-logic abuse, chained attacks, complex authorization relationships, design flaws, and social
> engineering. Those need threat modeling, manual testing, and security review."
