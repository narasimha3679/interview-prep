# SQL Server — Easy Interview Query Questions

Practice the common **“find this, find that”** round. Try to write each query before reading the
answer. All answers use **Microsoft SQL Server (T-SQL)** and the schema below.

**Compatibility:** SQL Server 2012+ for the `OFFSET ... FETCH` answer; the other queries work on
older supported versions unless noted.

## Practice schema

An order is assigned to the employee who handled it. `NULL` in `ManagerID` means the employee has
no manager; `NULL` in `DepartmentID` means the employee is unassigned.

```sql
CREATE TABLE dbo.Departments
(
    DepartmentID   INT          NOT NULL,
    DepartmentName VARCHAR(100) NOT NULL,
    CONSTRAINT PK_Departments PRIMARY KEY (DepartmentID)
);

CREATE TABLE dbo.Employees
(
    EmployeeID   INT           NOT NULL,
    FullName     VARCHAR(100)  NOT NULL,
    Email        VARCHAR(255)  NULL,
    DepartmentID INT           NULL,
    ManagerID    INT           NULL,
    Salary       DECIMAL(12,2) NOT NULL,
    HireDate     DATE          NOT NULL,
    IsActive     BIT           NOT NULL
        CONSTRAINT DF_Employees_IsActive DEFAULT (1),
    CONSTRAINT PK_Employees PRIMARY KEY (EmployeeID),
    CONSTRAINT FK_Employees_Departments FOREIGN KEY (DepartmentID)
        REFERENCES dbo.Departments (DepartmentID),
    CONSTRAINT FK_Employees_Manager FOREIGN KEY (ManagerID)
        REFERENCES dbo.Employees (EmployeeID)
);

CREATE TABLE dbo.Orders
(
    OrderID    INT           NOT NULL,
    EmployeeID INT           NULL,
    Amount     DECIMAL(12,2) NOT NULL,
    Status     VARCHAR(20)   NOT NULL,
    OrderDate  DATETIME2(0)  NOT NULL,
    CONSTRAINT PK_Orders PRIMARY KEY (OrderID),
    CONSTRAINT FK_Orders_Employees FOREIGN KEY (EmployeeID)
        REFERENCES dbo.Employees (EmployeeID)
);
```

> In application code, pass values such as department names and dates as parameters. Literal values
> below keep the interview examples short.

## Basic filtering

### 1. Find all active employees, highest salary first

```sql
SELECT EmployeeID, FullName, Salary
FROM dbo.Employees
WHERE IsActive = 1
ORDER BY Salary DESC, EmployeeID;
```

**Trap:** `IsActive` is a SQL Server `BIT`, so compare it with `1` or `0`. `EmployeeID` makes the
order deterministic when salaries tie.

### 2. Find all employees in the Engineering department

```sql
SELECT e.EmployeeID, e.FullName, d.DepartmentName
FROM dbo.Employees AS e
INNER JOIN dbo.Departments AS d
    ON d.DepartmentID = e.DepartmentID
WHERE d.DepartmentName = 'Engineering'
ORDER BY e.FullName;
```

**Trap:** An `INNER JOIN` excludes employees with no matching department. Use a `LEFT JOIN` only
when those employees must remain in the result.

### 3. Find employees whose names start with A

```sql
SELECT EmployeeID, FullName
FROM dbo.Employees
WHERE FullName LIKE 'A%';
```

**Trap:** `%` means any sequence of characters; `_` means one character. Case sensitivity depends
on the column's collation.

### 4. Find employees who are not assigned to a department

```sql
SELECT EmployeeID, FullName
FROM dbo.Employees
WHERE DepartmentID IS NULL;
```

**Trap:** Use `IS NULL`, not `= NULL`. Comparisons with `NULL` evaluate to `UNKNOWN`, not `TRUE`.

### 5. Find employees hired during 2025

```sql
SELECT EmployeeID, FullName, HireDate
FROM dbo.Employees
WHERE HireDate >= '20250101'
  AND HireDate <  '20260101'
ORDER BY HireDate;
```

**Trap:** Prefer a half-open range (`>= start`, `< next start`). It also works for `DATETIME2`
columns without missing rows late on the last day. `yyyymmdd` is an unambiguous SQL Server date
literal format.

## Salary and aggregation questions

### 6. Find the employee or employees earning the highest salary

```sql
SELECT EmployeeID, FullName, Salary
FROM dbo.Employees
WHERE Salary = (SELECT MAX(Salary) FROM dbo.Employees);
```

**Trap:** `MAX(Salary)` returns only the value. The outer query returns the matching people and
correctly includes ties.

### 7. Find the top three highest-paid employees

```sql
SELECT TOP (3) EmployeeID, FullName, Salary
FROM dbo.Employees
ORDER BY Salary DESC, EmployeeID;
```

**Trap:** This returns exactly three rows when enough employees exist and can split a salary tie.
If every employee tied at third place must be included, use `TOP (3) WITH TIES` and order only by
`Salary DESC`.

### 8. Find the second-highest distinct salary

```sql
SELECT Salary
FROM
(
    SELECT DISTINCT Salary
    FROM dbo.Employees
) AS Salaries
ORDER BY Salary DESC
OFFSET 1 ROWS FETCH NEXT 1 ROWS ONLY;
```

**Trap:** Use `DISTINCT` so two employees with the same highest salary do not make that salary
appear to be second. For the Nth salary, use `OFFSET N - 1`; the result is empty when fewer than N
distinct salaries exist.

### 9. Find employees earning more than the company average salary

```sql
SELECT EmployeeID, FullName, Salary
FROM dbo.Employees
WHERE Salary > (SELECT AVG(Salary) FROM dbo.Employees)
ORDER BY Salary DESC;
```

**Trap:** The subquery returns one aggregate value for the whole table. Do not add `GROUP BY`
unless you need an average per group.

### 10. Find the employee count per department, including empty departments

```sql
SELECT d.DepartmentID, d.DepartmentName, COUNT(e.EmployeeID) AS EmployeeCount
FROM dbo.Departments AS d
LEFT JOIN dbo.Employees AS e
    ON e.DepartmentID = d.DepartmentID
GROUP BY d.DepartmentID, d.DepartmentName
ORDER BY d.DepartmentName;
```

**Trap:** Start from `Departments` and use `LEFT JOIN`. `COUNT(*)` would count the preserved row
for an empty department as one; `COUNT(e.EmployeeID)` correctly returns zero.

### 11. Find departments with more than two employees

```sql
SELECT d.DepartmentID, d.DepartmentName, COUNT(e.EmployeeID) AS EmployeeCount
FROM dbo.Departments AS d
INNER JOIN dbo.Employees AS e
    ON e.DepartmentID = d.DepartmentID
GROUP BY d.DepartmentID, d.DepartmentName
HAVING COUNT(e.EmployeeID) > 2
ORDER BY EmployeeCount DESC, d.DepartmentName;
```

**Trap:** `WHERE` filters rows before grouping; `HAVING` filters groups after aggregation. The
`INNER JOIN` is sufficient because empty departments cannot pass the threshold.

### 12. Find the average salary per department, highest average first

```sql
SELECT d.DepartmentID, d.DepartmentName, AVG(e.Salary) AS AverageSalary
FROM dbo.Departments AS d
INNER JOIN dbo.Employees AS e
    ON e.DepartmentID = d.DepartmentID
GROUP BY d.DepartmentID, d.DepartmentName
ORDER BY AverageSalary DESC, d.DepartmentName;
```

**Trap:** Every non-aggregated selected column must appear in `GROUP BY`. This version excludes
empty departments, whose average would be `NULL`.

## Duplicates, orders, and self-joins

### 13. Find duplicate email addresses

```sql
SELECT Email, COUNT(*) AS DuplicateCount
FROM dbo.Employees
WHERE Email IS NOT NULL
GROUP BY Email
HAVING COUNT(*) > 1
ORDER BY Email;
```

**Trap:** The query finds the duplicated values, not all the underlying rows. Whether `'A@x.com'`
and `'a@x.com'` match depends on the collation.

### 14. Find all employee rows whose email address is duplicated

```sql
WITH DuplicateEmails AS
(
    SELECT Email
    FROM dbo.Employees
    WHERE Email IS NOT NULL
    GROUP BY Email
    HAVING COUNT(*) > 1
)
SELECT e.EmployeeID, e.FullName, e.Email
FROM dbo.Employees AS e
INNER JOIN DuplicateEmails AS d
    ON d.Email = e.Email
ORDER BY e.Email, e.EmployeeID;
```

**Trap:** Do not delete rows from this result without a separate keep-rule, such as the lowest
`EmployeeID` or latest `HireDate`.

### 15. Find employees who have no orders

```sql
SELECT e.EmployeeID, e.FullName
FROM dbo.Employees AS e
WHERE NOT EXISTS
(
    SELECT 1
    FROM dbo.Orders AS o
    WHERE o.EmployeeID = e.EmployeeID
)
ORDER BY e.EmployeeID;
```

**Trap:** `NOT EXISTS` is a safe anti-join. `NOT IN` can return no rows if the subquery's compared
column contains `NULL`.

### 16. Find each employee's order count and total amount, including employees with no orders

```sql
SELECT
    e.EmployeeID,
    e.FullName,
    COUNT(o.OrderID) AS OrderCount,
    COALESCE(SUM(o.Amount), 0.00) AS TotalAmount
FROM dbo.Employees AS e
LEFT JOIN dbo.Orders AS o
    ON o.EmployeeID = e.EmployeeID
GROUP BY e.EmployeeID, e.FullName
ORDER BY e.EmployeeID;
```

**Trap:** Use `COUNT(o.OrderID)`, not `COUNT(*)`, and convert the unmatched `SUM` from `NULL` to
zero with `COALESCE`.

### 17. Find employees whose completed orders total more than 1,000

```sql
SELECT e.EmployeeID, e.FullName, SUM(o.Amount) AS CompletedTotal
FROM dbo.Employees AS e
INNER JOIN dbo.Orders AS o
    ON o.EmployeeID = e.EmployeeID
WHERE o.Status = 'COMPLETED'
GROUP BY e.EmployeeID, e.FullName
HAVING SUM(o.Amount) > 1000.00
ORDER BY CompletedTotal DESC, e.EmployeeID;
```

**Trap:** Filter statuses in `WHERE` before aggregation and the total in `HAVING` after
aggregation. Employees with no completed orders cannot pass this threshold.

### 18. Find the latest order for each employee

```sql
WITH RankedOrders AS
(
    SELECT
        o.OrderID,
        o.EmployeeID,
        o.Amount,
        o.Status,
        o.OrderDate,
        ROW_NUMBER() OVER
        (
            PARTITION BY o.EmployeeID
            ORDER BY o.OrderDate DESC, o.OrderID DESC
        ) AS RowNumber
    FROM dbo.Orders AS o
    WHERE o.EmployeeID IS NOT NULL
)
SELECT OrderID, EmployeeID, Amount, Status, OrderDate
FROM RankedOrders
WHERE RowNumber = 1
ORDER BY EmployeeID;
```

**Trap:** `ROW_NUMBER` returns one order per employee; `OrderID` breaks date ties. Employees with
no orders are absent. Use a `LEFT JOIN` from `Employees` if they must appear too.

### 19. Find each employee with their manager's name

```sql
SELECT
    e.EmployeeID,
    e.FullName AS EmployeeName,
    m.FullName AS ManagerName
FROM dbo.Employees AS e
LEFT JOIN dbo.Employees AS m
    ON m.EmployeeID = e.ManagerID
ORDER BY e.EmployeeID;
```

**Trap:** This is a self-join: the same table has two aliases. `LEFT JOIN` keeps top-level
employees whose `ManagerID` is `NULL`.

### 20. Find employees who earn more than their manager

```sql
SELECT
    e.EmployeeID,
    e.FullName AS EmployeeName,
    e.Salary AS EmployeeSalary,
    m.FullName AS ManagerName,
    m.Salary AS ManagerSalary
FROM dbo.Employees AS e
INNER JOIN dbo.Employees AS m
    ON m.EmployeeID = e.ManagerID
WHERE e.Salary > m.Salary
ORDER BY e.EmployeeID;
```

**Trap:** An `INNER JOIN` intentionally excludes employees without a manager because there is no
manager salary to compare.

## Quick follow-ups interviewers ask

| Follow-up | Short answer |
|---|---|
| Why add a tie-breaker to `ORDER BY`? | Pagination and “latest/top N” results become deterministic. |
| `WHERE` vs `HAVING`? | `WHERE` filters input rows; `HAVING` filters aggregated groups. |
| `INNER JOIN` vs `LEFT JOIN`? | Matches only vs all left rows plus matches. |
| `COUNT(*)` vs `COUNT(column)`? | Rows vs non-`NULL` values in that column. |
| Why `NOT EXISTS` for missing related rows? | It expresses an anti-join and avoids the `NOT IN`/`NULL` trap. |
| `ROW_NUMBER` vs `RANK`? | `ROW_NUMBER` gives one unique sequence; `RANK` gives ties the same rank and leaves gaps. |
| How do you return tied top salaries? | Use `TOP ... WITH TIES`, or `RANK`/`DENSE_RANK` depending on the requirement. |
| Why use a date range instead of `YEAR(HireDate) = 2025`? | A direct range on the column can use an index seek; wrapping the column in a function usually prevents that. |
