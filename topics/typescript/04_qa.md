# 04 — TypeScript Q&A

**T1. Why TypeScript for test automation?**
> "Compile-time safety, better refactoring, autocomplete, and explicit contracts for page objects and
> API models. It catches null/undefined and shape errors before the test runs. It does not replace
> runtime validation or assertions."

**T2. `interface` vs `type`?**
> "Both describe object shapes. Interfaces are extendable and mergeable; type aliases handle unions,
> intersections, and primitives. I use interfaces for extendable models and type aliases for unions."

**T3. `any` vs `unknown`?**
> "`any` disables type checking; `unknown` is safe and must be narrowed before use. I use `unknown`
> at boundaries and narrow with guards/schema validation."

**T4. What is narrowing?**
> "Refining a union to a specific member using `typeof`, `in`, `instanceof`, or a discriminant field.
> It lets me handle each variant safely."

**T5. What are generics?**
> "Type parameters that let a function/class work with many types while preserving safety. I use them
> for API responses (`ApiResponse<T>`) and pagination (`Page<T>`)."

**T6. What is a type guard?**
> "A function that returns `value is T`, telling the compiler the runtime type after the check. I use
> them at JSON/API boundaries."

**T7. Do TypeScript types validate API responses?**
> "No. Types are erased at runtime. A cast is a claim, not proof. I validate with Zod/guards when the
> response is external or critical."

**T8. How does async/await work?**
> "It is syntax over Promises. `await` pauses the async function until the promise settles. I must
> await every promise I depend on, or the test continues too early."

**T9. Why is `forEach(async ...)` a bug?**
> "`forEach` does not await the callback, so the loop finishes before the async work. Use `for...of`
> for sequential work or `Promise.all` for parallel work."

**T10. `Promise.all` vs `for...of`?**
> "`Promise.all` runs independent work concurrently and fails fast; `for...of` runs sequentially. I use
> parallel only when the operations are independent and safe to run concurrently."

**T11. How do you handle errors?**
> "`try/catch`, preserve the cause, add context (test/user/endpoint), and rethrow. I don't swallow
> errors or catch and continue silently."

**T12. What is a Playwright fixture?**
> "A dependency-injection mechanism that sets up a value per test and tears it down. I use typed
> fixtures for page objects and API clients so each test gets isolated, ready-to-use dependencies."

**T13. Why page objects?**
> "They centralize locators and user-level actions. A selector change is one edit; specs describe
> behavior. They also keep tests readable and reusable."

**T14. How do you keep tests isolated?**
> "Playwright creates a fresh browser context/page per test; fixtures construct page objects per
> test; data is unique per test; no shared mutable state; auth state is generated."

**T15. How do you avoid flaky waits?**
> "Use auto-waiting locators and web-first assertions; wait for a specific state, not time. Never use
> `waitForTimeout` except for debugging."

**T16. How do you type an API response?**
> "Define an interface/type for the contract, then validate at runtime if the API is external or
> critical. For internal APIs with a generated client/schema, use the generated types."

**T17. What is `tsconfig` strict mode?**
> "A set of checks including `strictNullChecks`, `noImplicitAny`, and more. It catches null/undefined
> and implicit-any bugs that become runtime failures. I enable it for framework code."

**T18. Why `tsc --noEmit` in CI?**
> "Playwright transpiles without full typechecking. `tsc --noEmit` catches type errors across the
> framework before tests run."

**T19. How do you manage config?**
> "Environment variables for URLs/secrets, `.env` locally, CI secrets in the pipeline, fail fast on
> missing required values. Never commit `.env` or auth state."

**T20. How would you refactor a messy Playwright test?**
> "Extract page objects and typed fixtures, replace CSS/XPath with role/test-id locators, remove
> fixed sleeps, move API setup out of the UI, make data unique, and add trace/report artifacts."
